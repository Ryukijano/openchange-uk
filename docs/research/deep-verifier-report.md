# Verification report: claims (a)\u2013(i) for the scaling / shift / planning study\n\nChecked 2026-10-07 against primary sources: papers (arXiv abstract/HTML), official repo files, Hugging Face (HF) dataset/model cards and API metadata, Isambard docs, GOV.UK. Web reading only: nothing cloned, downloaded for use, trained, or run on Isambard.\nLabels: **VERIFIED** = the primary source says it. **FALSE** = the primary source says something else (corrected value given). **UNVERIFIED** = I could not find a primary source either way. Lines marked *Inference* are my reasoning, not something a source states.\n\n## Corrections that change the design (read first)\n\n1. **The training-grid budget is about 2\u00d7 too low if every model size runs at every FLOP level.** Four sizes \u00d7 4 levels/decade from 1e17 to 3e21 FLOPs = 76 runs and **\u224823,200 GPU-h for one seed** at 35% MFU, not 10\u201312k. The four 3e21 runs alone cost \u22489,600 GPU-h. The staged plan fits only because Stage 2 stops at 1e21 (36 runs \u2248 7,300 GPU-h per seed). Stage 1 (1e17\u20131e19, 36 runs) is only \u224873 GPU-h of training per seed, so its 8,000 GPU-h line is nearly all evaluation. Fix the grid shape in BUDGET_DESIGN before costing anything else.\n2. **Closed-loop evaluation, not training, is the largest cost.** At the notes' own figure (1.5e17 FLOPs \u2248 7.2 GPU-min per CEM episode), 500 episodes \u00d7 70 models \u00d7 5 planner budgets \u2248 **21,000 GPU-h**. That figure also assumes ~250 predictor tokens per forward pass. If the predictor runs on all V-JEPA tokens per state (thousands), cost goes up by more than 10\u00d7. Fix the predictor token count first, then size the evaluation grid.\n3. **Feature-cache sizes are off for V-JEPA 2.1 ViT-g/G.** ViT-g has embed_dim 1408 and ViT-G 1664, not 1024. At 4096 tokens in BF16 that is 11.5 MB (g) or 13.6 MB (G) per clip, not 8 MB, so a 5k-hour cache is roughly 50\u201360 TB, not 35. Also, the official 2.1 configs are 256 px / 16 frames, which with tubelet 2 and patch 16 gives **2048 tokens**, not 4096. Decide on resolution and frames, then recompute.\n4. **TokaMark's licence is CC-BY-4.0, not CC-BY-SA-4.0** (official UKAEA-IBM-STFC HF card). The raw release is ~565 GB, 11,573 MAST shots, 39 signals, 14 tasks. For the fusion option this is good news: attribution only, no share-alike.\n5. **HydroGym has no aarch64 Docker images** (every published tag is amd64), and Isambard runs Podman-HPC/Apptainer, not Docker. The per-step CPU wall time I could not find anywhere. Budget a CPU-only Firedrake build-and-time pilot before committing to HydroGym as the control substrate.\n6. **Pick datasets with a real held-out parameter axis, and choose the licence per source.** Robot-video licences are mixed. 1X raw video is CC-BY-NC-SA. Ego4D needs a signed, non-transferable agreement with no redistribution. InternW0-\u0394 data is an aggregate of third-party datasets, each keeping its own licence. A "shifted" split built from such sources must be licence-filtered first.\n7. **VIScore (arXiv 2608.11174) v2 has been withdrawn / removed by arXiv administrators** (licence-rights issue). Do not cite it as evidence.\n8. **The threatening papers are small-scale and narrow.** DRPE uses a factored gridworld. The Objective paper is one LeWorldModel reproduction on TwoRoom. Rubik is a single synthetic task. Unreliable and Schaeffer are about LLMs. *Inference:* they make "loss predicts planning" an open question, which suits a pre-registered test. They also mean the study has to measure decision-relevant / planner-reachable error and vary the planner objective as its own factor, rather than read decision quality off average loss.\n\n## Summary table\n\n| # | Claim | Verdict | Corrected / exact value | Primary source |\n|---|---|---|---|---|\n| a1 | The Well: 16 datasets, 15 TB | VERIFIED | 16 datasets, 15 TB | https://arxiv.org/abs/2412.00568 |\n| a2 | Data licence CC-BY-4.0 per dataset | VERIFIED (with caveat) | Paper datasheet: data CC-BY-4.0; generating code CC-BY-4.0 where releasable.
