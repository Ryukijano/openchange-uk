# OpenChange-UK: data/model feasibility for a public HF demo

**Audit date: 13 October 2026. Research only.** Primary dataset cards, documentation, source code and public metadata/HEAD checks. No imagery, embeddings or weights downloaded; no training, implementation, repo edits, publication or cluster access. Skill guidance used: satellite imaging, geospatial ML, HF datasets, gap-to-topic and deep research. Their training/deployment steps were deliberately not executed.

## Verdict

**Lowest-friction useful product:** a bounded, user-trained annual mapping/export tool using released **TESSERA v1.1-dclimate** embeddings. Users supply labelled points and candidate sites; receive predictions, unsupported/missing-site flags and downloadable GeoJSON/CSV. Packaged forest examples can use DISFOR **only after its dataset licence/ancillary-label obligations are checked**. This is retrospective annual evidence, not live deforestation alerts and not sensor fallback.

**Lowest-friction actual S1/S2 mechanics pilot:** the newly located **TorchGeo PASTIS-R-100** HF subset: 100 paired crop time-series samples in a **2.039 GB** archive, rather than 53.7 GB. Pair it with **AnySat base** and separately validated availability-specific heads. It can demonstrate real inference on SAR-only inputs, but packaged historical examples remain replay; crop results cannot establish forest reliability. First-100 geography, contents and class coverage are not yet inspected, so it is a feasibility/smoke subset until audited.

**No verified turnkey forest fallback product** emerged. AnySat and CROMA provide usable pretrained sensor encoders, not a published, validated forest triage head with guaranteed sensor/model-transition reliability. Real new-input fallback is technically possible after preprocessing/head fitting and held-out validation; without that work v1 must be labelled replay/exploratory inference, not an operational monitor.

## 2. Released models: independent weight audit

### AnySat base — preferred paired time-series baseline

- Code MIT; **official HF weight card separately declares MIT**. Anonymous HF API reports ungated. Release revision `63f252119babfe896d200f88631496f86eddacd3`; `models/AnySat.pth` **503,756,453 B**, SHA-256 `ce1246527a28bade624048c448a1fa473ca85791b998f562ce2bcc3dcac93d4f`.
- README and loader require S2 `B×T×10×H×W`, bands B2/B3/B4/B5/B6/B7/B8/B8A/B11/B12, dates in day-of-year, `(x−mean)/std`, matching physical extents. S1 path accepts three channels VV/VH/ratio; separate `s1-asc` stem accepts VV/VH. **Ratio definition, units, orbit policy and normalization must match the selected dataloader; do not invent them.**
- Arbitrary supported modality combinations are documented; PyTorch loader defaults to CPU, supports `flash_attn=False`. **Only base has a checkpoint URL** in inspected `hubconf.py`; tiny/small constructors are not proof released tiny/small weights exist.
- GeoPlex pretraining includes **PASTIS-HD** and TreeSatAI-TS. PASTIS-R derived imagery/locations may overlap pretraining, so this baseline comparison is practical use, **not unseen-region transfer evidence**. Separate availability-specific heads/calibration remain necessary even with equal feature dimensions.
- HF runtime was not benchmarked. Roughly 504 MB checkpoint plus activations/dependencies is feasible to investigate; no CPU latency or concurrency guarantee. Offline precomputed examples avoid startup/inference delays.

### CROMA base — simpler single-date alternate

- Code MIT; HF API/card metadata **separately declares MIT**, although body is essentially empty. Ungated revision `0dd28e3d633bd6715856ae9890e8c49360040598`; `CROMA_base.pt` **777,563,846 B**, SHA-256 `0238d814b53108f3574bf1ea240e38a0a6edd46173816d9a6962070561893b63`.
- Actual loader supports `modality='SAR'`, `'optical'`, `'both'`: **`both` asserts both inputs exist**, so real optical absence requires the SAR path, not zeros masquerading as observations. Two S1 bands, **12 S2 bands**, square image side multiple of eight, default 120; returns 768-D base sensor features.
- Published normalization rescales/clips per band; freeze and document its scope so results do not silently depend on the other users/images in a batch. **PASTIS/DISFOR ten-band S2 is incompatible with the twelve-band optical stem** without justified new preprocessing. Do not pad missing atmospheric bands and claim equivalence.
- No released turnkey forest head verified. These encoders do not themselves guarantee that an optical-trained head works on radar features.

TESSERA remains a strong frozen-feature/annual mapping baseline, not a substitute for a fresh SAR-only observation. No evidence here establishes teacher-free shared-ViT superiority, Gaussian-marginal alignment, or safe checkpoint migration.

**Austria labels remain a separate gate.** Parent's 13 October local inspection found only a `crop` property, with no source/year/licence fields. The official tessera-eval README describes 349 parcels and uses 2024, but this does not independently establish the labels' year or provenance. Its advertised RF ≈0.80 under five-fold pixel CV is not comparable to the earlier ≈0.13 parcel spatial-held-out result. MIT code does not establish label redistribution rights. Do not package these labels or treat them as a cleared replacement for DISFOR/PASTIS.

## 3. Proposed ≤500-site pilot and versioned data contract

**Two deliberately separate gates, not two simultaneous full projects.**

### A. Useful mapping/export product: ≤500 forest points

After exact approval, fetch DISFOR sample/label tables and select **at most 500 unique sites** across available disjoint geographic/event clusters. Use only sufficiently documented labels. Request same-year TESSERA vectors for selected sites, pinned v1.1-dclimate; initial target 2024 if label availability supports it. ≤500×128 float32 values are only 256 KB of logical output; **actual chunk transfers can be much larger**. No imagery needed initially.

Target either year-end disturbance-evidence triage or clearly defined stable land-state categories. Interval/event labels cannot automatically become dense image masks. Full-year embeddings can incorporate post-event observations: label this **retrospective**, never causal/early warning. Exclude incomplete-year interpretation and ambiguous transitions rather than imputing exact onset dates.

PROPOSED split budget: 200 head-training sites / 100 unlabelled old–new alignment sites / 100 distinct labelled calibration sites / 100 locked geographic test sites. Every site and connected geographic/event cluster belongs to exactly one role; repeated years stay with that role. Require enough separate clusters/classes before accepting these counts. Future-year evaluation must also be held out if available; otherwise explicitly untested. Alignment/calibration cannot reuse head-training sites as in the earlier Vienna exploration.

Freeze a modest regularized head and save its validation history. Compare old head on old features, old head on raw new features, identity/Procrustes/ridge mappings learned on **alignment only**, and newly fitted head; calibrate on separate calibration sites, evaluate on locked test. If old/new releases differ in model **and production run**, this measures combined product migration, not isolated encoder changes. For teacher-free checkpoints later, hold imagery/preprocessing fixed.

### B. Actual availability mechanics: ≤100 crop tiles

Separate approval for TorchGeo's 2.039 GB PASTIS-R-100 archive plus AnySat base. First inspect contents, geographic spread, parcel IDs, dates, clear-mask availability and class counts. Fit small heads offline on frozen features for S2-only, S1-only and paired inputs. Test the **same sites** with full observations, declared sensor absence, realistic contiguous optical gaps and recovery. PASTIS contains cloudy observations but no verified mask sufficient to infer true missingness here; synthetic withholding must be explicitly labelled simulated. If the subset is geographically compact, keep this to a UI/contract test; do not claim region/future generalisation.

### Contract `openchange-demo/v0.1` (proposal)

Each sample carries `site_id`, `task_id`, geometry/CRS/affine/pixel size, acquisition timestamps, observation window, label time/support (point, parcel or raster), split role, geographic/event group, confidence, source URLs, attribution, dataset revision/checksums and each asset's licence. Sensor payload additionally records product level, band order, units/scaling, orbit, resampling, normalization ID, cloud/nodata/availability masks. Absence is an explicit state, never a valid-looking zero image.

Each feature/head artifact carries encoder/checkpoint digest, dataset version **and variant**, preprocessing digest, feature schema/dimension, aggregation window, head-training sites, calibration sites, supported sensors/classes/geography/time, adapter version and immutable validation record. Block mismatched inputs; keep legacy heads and history readable rather than overwriting them.

Each downloadable prediction carries score/class, empirical calibration support, availability regime, withheld/unsupported reason, model/head/data versions and timestamps. Missing coverage returns no prediction. Forest evidence is not a legal finding of deforestation or its cause. An export includes manifest/attribution plus CSV and GeoJSON; GeoTIFF only for genuinely georeferenced raster predictions, never fabricated dense truth from labelled centre pixels.

## 4. Ready-to-use public workflow and release gates

**Packaged offline examples:** 3–6 representative labelled-site sets and their bounded candidate maps, feature vectors, frozen heads, compatibility comparisons and hold-out validation records. Select examples by declared regimes, **not attractive model results**. Display map geometry, annual feature preview and evidence dates; add true optical/SAR thumbnails only when approved data assets/georeferencing/rights are checked. No dependency on a user entering GEE/Copernicus credentials for examples.

**Genuinely new input, CPU-first:** browser-upload labelled GeoJSON/CSV and bounded candidate points/AOI within published TESSERA years. Retrieve only approved bounded public features; fit a tiny head, report validation limitations, export candidates. Enforce site/area/time/transfer limits and explicit missing coverage. A user-trained map is useful even when the label schema differs from forest examples; it is not a certified model for arbitrary geography.

**Genuinely new S1/S2 input, later:** accept a size-limited, preprocessed georeferenced sensor bundle with manifest, dates and masks; run AnySat plus an already validated head. A TIFF lacking band/units/orbit metadata must be rejected. Do not accept arbitrary uploaded pickle checkpoints. Automatic arbitrary-place/date satellite acquisition would introduce new access, preprocessing, bandwidth and validation work; it is outside v1. A historical gap-slider is replay even if the underlying inference is real.

**Compact evaluation:** macro F1 / balanced accuracy plus per-class precision–recall; retained-head score and calibration degradation; abstention risk–coverage; paired-vs-SAR-only/gap/recovery strata; interval-aware timing only where labels support it. Bootstrap spatial/event groups, not independent pixels/parcels. Compare simple spectral/time-series head and incumbent/frozen pretrained baselines. Q1 cheap checkpoint selection needs actual checkpoints and full-selection reference runs: rank with held-out calibration probes, then test whether the inexpensive choice preserves downstream quality. Data availability alone cannot establish this.

**Kill / narrow-scope criteria (proposed before looking at results):**

1. Ambiguous mask/ancillary rights or conflicting licences: no redistribution; switch data or obtain clarification.
2. Too few independent geography/event groups or class support: smoke demo only, no reliability/transfer claim.
3. Missing compatible band/unit/time/georeferencing contract: reject input, not zero-fill missing bands.
4. No independent calibration/test sites, poor base classifier, or unacceptably wide uncertainty: no safe-migration claim. Predeclare allowable degradation and minimum coverage before measurement; if mapping fails, retain old encoder/head or require refit.
5. Radar-only performance/calibration unsupported on actual gap regimes: no operational fallback promise. Crop mechanics cannot validate forest alerts.
6. Public-store point access or capped region export exceeds feasible transfer/latency: offline examples plus user-uploaded **feature+manifest** mode; do not quietly fetch whole global archives.
7. Annual embeddings cannot answer the desired monthly/live question: change the workflow or obtain new approved observation data; do not mislabel annual evidence as current sensing.
