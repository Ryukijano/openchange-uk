# What we have done so far

Updated 15 October 2026. This is the current summary; older proposals are retained
as history, not as instructions to train or deploy.

## The goal

Build a useful Hugging Face Space that helps someone make a defensible
Earth-observation decision, without needing their own compute server. Research
must establish that the capability works before the demo presents it as useful.

The working order is:

**Useful task → failure of existing methods → independent target and suitable
data → training objective → architecture → public demo.**

JEPA, continued pretraining and training from scratch are options, not commitments.
We have not established that a new foundation model is needed.

## 1. How we chose the task

We first considered preserving downstream maps through encoder upgrades. A
TESSERA pilot tested that idea, but did not establish useful mapping accuracy or
saved work. We then compared forecasting/next-observation selection, coastal
measurement, disaster mapping, restoration-effect assessment and event retrieval.

The important distinctions were:

- Existing mapping and alert interfaces are not, by themselves, a scientific gap.
- Satellite greenness is not proof of a causal restoration effect.
- Labels generated by another algorithm are not independent physical truth.
- Retrieval by shape/severity does not automatically need a trained encoder.
- Forecasts must not use future weather or observations unavailable at issue time.
- Coastal shoreline movement can reflect tide, waves, proxy choice or registration,
  rather than erosion or accretion.

We chose the last problem for the first cheap test because independent field
surveys provide a way to check the measurement. The proposed learned component
predicts the error of an existing satellite shoreline extraction; it does not
replace CoastSat/CoastSeg or claim to measure change directly from two pictures.

Two potentially overlapping papers were checked. The coastal signal-to-noise
paper was **abstract-only** because the full text was inaccessible; the S1/S2
forecasting paper was read in full. These checks narrowed the proposed claims;
they are not proof that the remaining idea is novel.

Read: [problem comparison](research/eo-task-research/notes/HIGHER_IMPACT_SCIENTIFIC_PROBLEMS.md),
[task-first plan](research/eo-task-research/notes/TASK_FIRST_TRAINING_PLAN.md),

## 2. The earlier TESSERA pilot

We compared 2024 embeddings from `v1.0/vultr` and `v1.1/dclimate` on 348 usable
Austrian crop parcels: 174 western parcels for fitting/alignment, 174 eastern
parcels for testing. One of the original 349 parcels had no usable finite labelled
pixels. Adapters used paired fitting features without labels.

| Random-forest route | Test macro-F1 | Decision churn versus old route |
|---|---:|---:|
| Old features + old head | 0.127 | 0.0% |
| New features + unchanged head | 0.061 | 27.0% |
| Procrustes + old head | 0.060 | 26.4% |
| Ridge + old head | 0.124 | 9.8% |
| New features + refitted head | 0.111 | 17.8% |

These are point estimates from the stored JSON. Earlier messages quoted 0.128
for the old route using the bootstrap mean; it is not the same statistic.
Ridge preserved this weak head better than no mapping, but absolute accuracy is
low. The transition changes both model version and inference run; it does not
isolate run drift. Label year/rights remain unresolved. No deployment-safety,
operational cost-saving or habitat-mapping claim follows.

Evidence: [pilot archive](../reports/tessera/2026-10-13/README.md).

## 3. Coastal Stage 0: one beach, later dates

The pinned [SDS_Benchmark](https://github.com/SatelliteShorelines/SDS_Benchmark)
clone contains the required raw surveys for Narrabeen, but not all the proposed
sites. We therefore registered a narrower repository-only temporal screen before
scoring, rather than presenting it as a four-site test.

The model used tide, waves, season, sensor and optionally CoastSat–SHOREX
disagreement. It had only **31 fitting scenes**. Whole scenes were kept together.

| Route, roughly 70% scene retention | Test RMSE |
|---|---:|
| Published position, unchanged (context comparison) | 6.74 m |
| Setup baseline selected on calibration (registered comparator) | 8.12 m |
| Metadata model | 8.43 m |
| Metadata + disagreement model | 8.41 m |

The learned conditions were respectively 3.9% and 3.6% worse than the
calibration-selected comparator. The frequently quoted 6.7 m comparison is the
unchanged published route, **not** that selected baseline. The
metadata+disagreement intervals averaged 36.68 m wide and made no confident
direction claims among 138 exploratory pairs. The metadata-only condition made
one; neither is a useful claim-coverage result or a test of independent pairs.

Evidence: [Stage 0 protocol, original log, results and code](../reports/coastal/2026-10-13-stage0/README.md).

## 4. Why the registered three-beach test stopped

The next protocol required at least **30 matched rows and 10 whole scenes in
every affected fit/calibration/test partition**, with survey matching within
±48 hours. Field-survey contours were reconstructed with fixed datum and
geometry rules, not shifted to make residuals smaller.

| Site | Fit rows / scenes | Calibration rows / scenes | Test rows / scenes |
|---|---:|---:|---:|
| Narrabeen | 138 / 31 | 194 / 45 | 329 / 68 |
| Truc Vert | **1 / 1** | **2 / 1** | **7 / 3** |
| Torrey Pines | Unavailable | Unavailable | Unavailable |

Truc Vert fails every split. All three fixed folds depend on it, so the test
stopped before model fitting. An independent count checker reproduced the
shortfall. Torrey's API/public downloads returned 401/403; an upload would not
rescue this protocol. We did not widen windows or replace transects after seeing
the counts.

This is **data insufficiency, not a model result**.

Evidence: [three-site audit](../reports/coastal/2026-10-13/README.md).

## 5. The replacement Narrabeen + Duck experiment

A counts-first catalogue audit suggested Duck was viable. We wrote a **new**
protocol; the stopped three-site protocol remains unchanged. Duck's USACE FRF
NetCDF metadata permits unrestricted use with acknowledgement. Only 169
survey files matching the fixed benchmark transects and scene dates were
downloaded: **157,193,250 bytes**, with per-file checksums.

Realised counts after contour exclusions:

| Site | All matched rows / scenes | Fit | Calibration | Test |
|---|---:|---:|---:|---:|
| Narrabeen | 661 / 144 | 138 / 31 | 194 / 45 | 329 / 68 |
| Duck | 679 / 204 | 252 / 77 | 79 / 22 | 348 / 105 |

Both pass the sample gate. The fitting cutoff is 2009-12-31, calibration is
2010–2016, and test dates begin in 2017. Calibration is on the **fitting beach**,
not the held-out beach.

We ran five cheap baselines first, then fixed quantile gradient-boosting
conditions (metadata, metadata + disagreement; seeds 0/1/2). Scenes are ranked
by absolute predicted median error. Reported retained RMSE evaluates the
**unchanged published shoreline positions** after selection; it is not the RMSE
after subtracting a predicted bias. Model fitting gives equal weight to scenes;
the reported RMSE itself is row-weighted.

### Primary outcome: failed

The project gate was **at least 15% retained-RMSE reduction on both held-out
beaches**, at approximately 70% scene retention. Lower RMSE is better.

| Fold | Calibration-selected baseline | Baseline RMSE | Metadata + disagreement RMSE | Relative reduction |
|---|---|---:|---:|---:|
| A: fit Duck → test Narrabeen | No-QC score (`unfiltered`) | 7.210 m | 6.830 m | **+5.3%** |
| B: fit Narrabeen → test Duck | Wave-only | 6.961 m | 7.960 m | **−14.3%** |

Mean relative reduction: **−4.5%**. Neither fold reaches +15%.
The metadata-only condition is also in the JSON: +3.4% in A and −27.0% in B.
All three seeds gave identical outputs at these deterministic HGB settings;
they are not three independent replications.

The nominal 90% quantile intervals covered approximately **68% / 79% of retained
rows** in A/B. This is not simultaneous scene coverage, pair coverage or a
new-site calibration guarantee. Unlike Stage 0, this runner does not apply
conformal widening. Planned bootstrap/per-sensor/pair secondary analyses are not
in its saved output and must not be described as completed.

Important comparator detail: the archived runner calls a constant-score,
approximately 70% subset `unfiltered`. It is **not all scenes** and not a random
control. Tied scores follow the archived sorting behaviour. We retain that
implementation and its output rather than change the reported result post hoc.

Evidence: [two-site report](../reports/coastal/2026-10-14/README.md),
[protocol](../reports/coastal/2026-10-14/code/protocol_narrabeen_duck_20261014.md),
[complete fold JSON](../reports/coastal/2026-10-14/evidence/fold_results.json).

## 6. What the negative result does—and does not—tell us

**Established:** this fixed metadata/disagreement head does not beat its cheap
baseline by the required margin across the two tested beaches. Its raw intervals
under-cover. The current configuration is not ready to support reliable
physical-change claims in a public tool.

**Not established:** the cause of failure; that image features will fix it; that
a different encoder/objective is needed; or that a coastal foundation model would
beat existing models. Metadata failure is not a justification for pretraining.

Limitations that remain visible:

- Only two beaches, with just 31 fitting scenes in the Narrabeen-source fold.
- Date-only surveys are interpreted as midnight UTC; close-time matching is
  approximate, not same-instant truth.
- Duck rejects 115 of 676 profile/date candidates. Accepted geometry has mean
  off-axis distance about 9.5 m and maximum about 230.6 m; those outliers were not
  silently removed.
- CoastSat–SHOREX disagreement is missing in about 29% of Duck rows.
- New sensors appear later; sensor, temporal and geographic shifts can interact.
- Historical code has workspace-specific paths. This is an evidence archive,
  not a clean-room, one-command reproduction release.

## 7. What would justify training next

The proposed next falsifier is a **separately approved imagery-aware comparison**:
first audit acquisition identifiers, rights, download/inference budget and
geometry; then compare strong physics/QC and metadata baselines with frozen
existing EO-encoder features under a new frozen protocol. Feature extraction
may require GPU inference even if the small head fits on CPU. This has not run.

Only a demonstrated gain would justify considering continued coastal pretraining
or fine-tuning. Survey-based post-training would learn measurement error and
abstention, not RLHF. A foundation-model claim would require reusable gains on
multiple independently labelled tasks, unseen regions/sensors and low-label
settings—not just one four-transect or two-beach head.

Per-site learning and the forecasting backup remain options, not running jobs.
No new imagery download, weights download, coastal pretraining, deployment or
cluster work is authorized by this publication.
